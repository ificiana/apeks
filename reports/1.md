# Report 1: four arms, seed 0, 6000 ticks

Runs from 2026-11-11, `logs/out_*_20261111-*.json` and matching traces. All arms share seed 0, the same network and the same scripted events:

| t | event |
| --- | --- |
| 1500 | storm forms at (600, 400) |
| 2500 | storm clears |
| 3000 | strait (W2–W3) blocked by a grounded vessel |
| 4000 | strait reopens |

LLM arms use `claude-haiku-5-5` through the Claude Code backend, latency 20 ticks, budget 20. Each LLM module was called 5 times (mission start plus once per event) with 0 failures and 0 skipped calls.

## Findings

1. **LLM routing is the largest effect.** It doubles deliveries over classical (38 vs 18) and cuts mean trip time by 41%. The gap opens after the storm: it delivers 16 in the last 2000 ticks against classical's 4.

2. **The LLM router avoids the strait from the start.** Every routing policy at mission start already lists `W2>W3` and `W3>W2` in `avoid`, before anything has happened there. The LLM arms send traffic through W2–W4 instead (`W2>W4`/`W4>W2` are among their most used lanes), while ACO keeps converging on the strait and the `ne>W3`/`W3>ne` corridor (22 strait traversals for classical). So the win comes partly from avoiding the strait in advance, not from reacting to events.

   The mission-start prompt never says the strait will be blocked. The model is reasoning from two cues in the prompt itself:
   - The situation's lane table shows W2>W3 and W3>W2 as the network's only narrow, single-file lanes (width 14, capacity 1; every other lane is width 50–60, capacity 2). A model that avoids bottlenecks would pick them out from this alone.
   - **The schema text gives `'W2>W3'` as its example lane id** ("Lane ids look like 'W2>W3'"). The one lane named in the instructions is the strait, which can nudge the model to put it in `avoid`.

   To separate these cues, the mission-start prompt was sent to `claude-haiku-5-5` 5 times in each of four variants, with the routing schema and no simulation. Each cell shows how many of the 5 replies avoided the strait:

   | variant | avoids strait |
   | --- | ---: |
   | original prompt | 3/5 |
   | example id changed to `'W1>W2'` | 4/5 |
   | strait widened to width 60, capacity 2 | 0/5 |
   | both changes | 0/5 |

   The lane table drives the choice: the model avoids the strait because the prompt shows it as the only single-file lane. Changing the example id makes no difference. With the strait drawn like any other lane, the model never avoids it. So this is a reasonable reading of the network data the policy is given, not a leak, and not knowledge of the scripted blockade. The choice is still a coin flip at 3–4 in 5, so whether a given run avoids the strait from t=0 is partly luck.

3. **ACO congests; LLM formation removes congestion but slows ships.** Classical logs 563 congestion ticks. LLM formation drives that to 0 and saves 20% energy, but trip time rises 13% and deliveries fall by one. Its policies widen spacing and `min_gap` at every event (spacing 15 → 30, min_gap 8 → 25) and lower `w_goal` to 0.5 during the blockade, so ships hold back.

4. **The combined arm is worse than LLM routing alone.** 25 deliveries vs 38. Two causes:
   - The slow, cautious formation policy from finding 3 sits on top of the router.
   - On "Strait reopened" (t=4000) the combined arm's router kept `avoid: [W2>W3, W3>W2]` with penalty 100 000, so the strait stayed closed for the rest of the run. The routing-only arm cleared `avoid` at that point. The two arms got different routing answers to the same event; one sample per arm cannot say whether the combined prompt context causes this or it is sampling noise.

5. **LLM formation cuts near misses.** Both LLM-formation arms and LLM routing have 66–90 near misses against classical's 129. Fewer ships in the busiest corridors explains part of the routing arm's drop.

6. **Total energy follows formation, but energy per delivery follows routing.** The two LLM-formation arms use ~134k in total against ~168–171k for the Boids arms. Energy counts distance pushed through the water, so a fleet that moves less spends less, whatever it delivers. Per delivery, the LLM-routing arms are cheapest (4 489 and 5 382 against classical's 9 327): shorter routes mean less sailing per cargo.

## Caveats

- One seed per arm. Differences of a few deliveries (classical 18 vs llm_formation 17) are within plausible noise; run several seeds before drawing conclusions from them.
- `blocked_discoveries` is 0 even for classical during the blockade, and the classical trace has 16 `notice_heard` records. Ships seem to learn of the blockade by radio notice before reaching it. Check whether the metric can ever be non-zero in this scenario.
- `wait_ticks` is 0 in every arm, so it does not discriminate between them in this scenario.
